# Public Site Security Checklist

This site is a GitHub Pages frontend with Supabase data and media storage.
The public model is intentionally read-only: visitors can view content, while
only the site owner can sign in and change it.

## One-time Supabase setup

1. Back up important tables and files from the Supabase Dashboard.
2. Open SQL Editor and run `supabase-security.sql` from this repository.
3. Open Storage > Policies. Review all existing policies on `storage.objects`.
   Delete any old policy that permits anonymous insert, update, or delete.
4. Run `supabase-storage-policies.sql` from this repository.
5. Open Authentication > Providers (or Settings) and disable new user signups.

The owner email in `supabase-security.sql` is currently
`2067229357@qq.com`. Change it before running the script if the owner account
uses a different email.

## Required verification

Use an incognito/private browser window, without logging in:

- Site content, photos, and songs load normally.
- There is no register option.
- Notes and playlist comments have no input box.
- Upload, delete, and edit controls are hidden.

Then log in with the owner account:

- Creating, editing, deleting, and uploading work normally.

The public navigation intentionally hides the login button. To access the
owner login UI, open the site with `?admin=1` appended to its address, for
example `https://translucent-i.github.io/?admin=1`. This only hides the UI;
Supabase authentication and RLS remain the actual security boundary.

If an anonymous upload or delete succeeds, stop sharing the site and inspect
the Storage policies again. Frontend hiding is not a permission boundary.

## What is deliberately public

The following data is readable by anyone who opens the site: public page
content, notes, playlist metadata, favorite records, photos, wallpapers, and
song files. Do not upload private photos, personal contact information,
location-sensitive material, passwords, API keys, or unreleased music.

The Supabase `anon` key in `index.html` is expected to be public. Never place
a Supabase `service_role` key in this repository or in browser code.

## Ongoing maintenance

- Keep only the media you want visitors to download in public Storage buckets.
- Check Supabase usage and storage egress periodically.
- Keep media sizes moderate; large audio files consume Storage download quota.
- After changing database tables or policies, retest in an incognito window.
